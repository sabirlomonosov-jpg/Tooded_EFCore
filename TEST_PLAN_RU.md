## Корзина-чек и переход к оплате

1. Откройте магазин: справа виден пустой чек, обе кнопки перехода к оплате выключены.
2. Добавьте два разных блюда и повторно одно из них: строки объединяются, количество и итог совпадают с ценами.
3. Измените количество в чеке мышью и клавиатурой. Сумма строки и итог обновляются сразу; превысить остаток нельзя.
4. Удалите строку кнопкой ×, затем другую количеством 0. Чек становится пустым, переход к оплате недоступен.
5. Добавьте позиции и нажмите «Edasi maksma» внизу чека или в шапке: открывается «Maksmine» с теми же товарами и итогом.
6. Закройте оплату без покупки: товары остаются в чеке. Удалите товар в окне оплаты и вернитесь: чек тоже обновлён.
7. Подтвердите покупку: создаётся PDF, остатки уменьшаются, после возвращения чек пуст, каталог показывает новый остаток.
8. Из другого окна администратора измените цену/остаток или удалите добавленный товар. Нажмите «Värskenda»: цена обновляется, недоступная строка остаётся видимой для удаления/уменьшения, оплата заблокирована до исправления.
9. Проверьте окно 1000×720 и развёрнутое окно; при длинном заказе строки чека прокручиваются, итог и кнопка оплаты остаются видны.

## Запуск и существующая база

- Проверьте первый запуск с отсутствующей базой и с пустой уже созданной базой: схема и меню создаются без повторного CREATE DATABASE.
- Запустите два экземпляра одновременно: подготовка базы сериализуется серверной блокировкой.
- Повторите запуск с действующей базой: цены, остатки, пользователи и история миграций сохранены.
- Если существующая база недоступна или выключена, показывается ошибка доступа/состояния; приложение не удаляет её и не создаёт замену.
- База с таблицами, но без совместимой истории миграций, требует отдельного разбора схемы. Не помечайте миграции выполненными вслепую и не удаляйте базу.

Дополнительная интеграционная проверка на отдельном SQL Server:

```powershell
# Установите TOODED_TEST_CONNECTION_STRING безопасным способом для тестового сервера.
dotnet run --project Tests/MenuChecks/MenuChecks.csproj -- --sql
```

Проверка создаёт базы с уникальными именами `Tooded_Test_*` и удаляет только созданные ею базы. Она проверяет новый/повторный запуск, существующую пустую базу и конкурентный запуск. Сервер должен разрешать создание тестовых баз. Без `--sql` выполняются только проверки меню, SQL-генерации и модели корзины.

## Восстановление недоступной базы

1. На Windows с доступной LocalDB и недоступной выбранной базой проверьте окно с ошибками 4060/18456 и явным предложением отдельного нового магазина.
2. Закройте окно: новый выбор не должен сохраняться, база не удаляется.
3. Повторите запуск и нажмите «Loo eraldi uus andmebaas»: после создания и миграций должен открыться вход с начальными учётными записями.
4. Убедитесь, что новая база имеет отдельное имя `Tooded_App_*`, старая база осталась нетронутой, а файл `database-name.txt` содержит только новое имя.
5. Измените цену, закройте и снова откройте приложение: должно использоваться то же новое хранилище, изменение цены сохранено.
6. При явно заданной `TOODED_CONNECTION_STRING` окно не должно предлагать её обход; приложение использует это подключение.
7. Если создание новой базы или её инициализация не удались, новое имя не должно сохраняться вместо прежнего выбора.
